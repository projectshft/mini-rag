## The idea in two sentences

AI agents now write a lot of the code, but they don't design the system, catch
their own mistakes or pass an interview for you. This program teaches a
beginner the fundamentals by hand first, then how to direct agents to build
real software and prove it works, then how to get hired.

## Who it's for

People changing careers, CS students and grads, product managers, and people
in tech who don't code yet. No experience needed. A product manager who has
never used Git should be able to start.

## The facts

- **Price:** $4,900. $0 down with Climb Credit. No income share agreements.
- **Length:** as little as 12 weeks, or as long as a year. Support for up to 12 months.
- **Start:** any time. No cohorts.
- **Mentor:** up to 12 one-on-one sessions with a working software engineer.
- **Also included:** weekly office hours, a monthly guest speaker, mock interviews and career support.
- **Where:** lessons and hand-ins are at ai.parsity.io.
- **What the student pays for separately:** about $20 a month for a coding agent. Claude is recommended and any tool is fine.
- **Languages:** JavaScript and TypeScript for projects. Any language for interview problems.

## How it works

- **By hand first.** The opening stretch is written with no agent at all, so the student can read and judge what an agent writes later.
- **Then with an agent.** From the second project on, the student plans a feature, has an agent build it, and checks the result.
- **Everything is handed in as a GitHub link and checked by tests.** The student's own tests run first, then tests they can't see. A failed hidden test names the kind of case that failed, never the test.
- **Unlimited resubmits. No deadlines.**
- **Each project ends with a short decision memo:** what the student chose and what it costs.
- **Interview problems, Git and GitHub, and LinkedIn run through the whole program,** so the job search doesn't start from zero at the end.

## What the student builds

1. A by-hand toolkit: their own array methods, a stack, a queue, a hash map and a test runner
2. A web server, built up from a raw network connection
3. One app built three ways
4. An order system that survives two orders arriving at the same moment
5. Login done three ways, attacked by a test suite
6. One app deployed two ways
7. A notification system that keeps working when the other side goes down
8. A capstone of their own: a real data source, an agent, and one technology the program never taught

## The five phases

| Phase | What it covers |
| --- | --- |
| Foundations | Terminal, Git and GitHub, tests, programming basics by hand, speed and Big O |
| The web | Networks, HTTP, servers, front ends, working with an agent |
| Data and trust | SQL and Postgres, auth, tests that prove something |
| Shipping and scale | Deploys, queues, system design |
| Capstone | The student's own product |

## Don't say

- "Course". Say program, or say what the student builds.
- "Spec" or "spec-driven development". Say "plan the feature first".
- "6 months", or any week count for a phase.
- How long a lesson or assignment takes.
- That it gets anyone a job, or that it's "a fraction of the time".
- Anything about a career coach, Redux, MongoDB, jQuery, a weather app, a Google Books app or a movie app. They're gone.
- No em dashes, no emojis, no hype.
